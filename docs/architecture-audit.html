How Vidpipe works

Vidpipe turns a short written brief into a narrated video in two languages. You give it a project folder; it walks the work through ten stages, asks a different tool for each job, and remembers what it already made so it never redoes work for nothing.

Part 1

The journey from brief to video

Every run goes through the same ten stages, in order. They fall into four phases: write the words, give them a voice, make the pictures, then add music and put it all together.

Write the words

Turn an idea into a script and a shot list.

  1. 1

    Brief

    Reads what you want the video to be from brief.md.

  2. 2

    Script

    Writes the narration lines.

    Uses a text AI (Gemini, Claude or Codex)
  3. 3

    Translation

    Writes the Amharic version, then translates it back to catch drift.

    Uses a text AI
  4. 4

    Storyboard

    Splits the script into shots, each with a camera move.

    Uses a text AI and the project bible

Give it a voice

Record the narration and make the timing fit.

  1. 5

    Narration

    Speaks each line in each language and measures how long it takes.

    Uses Edge TTS (English), Addis AI (Amharic)
  2. 6

    Fit planning

    Matches each shot's length to its narration, using a small speed change or an extra clip.

Make the pictures

Draw a still for every shot, then bring it to life.

  1. 7

    Keyframes

    Draws one still per shot, using the bible's character and location references.

    Uses FLUX.2 in ComfyUI
  2. 8

    Moving shots

    Animates each still. A longer shot continues from the previous clip's last frame.

    Uses Wan 2.2 in ComfyUI

Score and finish

Add music and assemble the final cut.

  1. 9

    Music

    Composes an instrumental score long enough for the longest version.

    Uses ACE-Step in ComfyUI
  2. 10

    Assembly

    Joins the clips, lowers the music under the voice and burns in subtitles. One MP4 and SRT per language.

    Uses FFmpeg

Behind every stage

  • The runner decides the order, pauses for your approval, and handles partial runs and single-shot redos.
  • The provider registry and doctor pick the tool your YAML names for each stage, and check that tool is actually installed.
  • The ledger remembers what each stage made, from which inputs, so unchanged work is reused.
  • The ComfyUI adapter sends image, video and music jobs to ComfyUI, retries failures and frees GPU memory.
Part 2

What needs attention

The audit found five problems. Two are high priority because they can silently produce wrong output. Each one below says what happens, why it matters, and what to change.

High

Changed files can be reused as if nothing changed

What happens

When deciding to reuse an output, Vidpipe checks its inputs and that the file exists, but not that the file's contents still match. Replacing a file with different bytes of the same size was still reused.

The fix

Check the stored hash before reusing an output, write outputs atomically, and give deliberate translation edits their own path.

All ten stagesLedger

Code: artifact store

High

Two runs at once can lose work

What happens

Two runs on the same project each saved a ledger record, and only the second survived. The demo script locks the GPU for its own callers, but the main CLI doesn't, so runs can still overlap on ComfyUI.

The fix

Allow only one writer per project across run, redo and approve, and coordinate GPU work per ComfyUI server.

All ten stagesRunnerLedgerComfyUI adapter

Code: ledger · GPU wrapper · ComfyUI lifecycle

Medium

Narration can only use one voice tool

What happens

The narration stage picks one adapter for every language. The Addis adapter works around this by passing English to Edge TTS, so the doctor only checked Edge and missed a missing Addis key.

The fix

Let the config pick a voice provider per language (keeping today's single setting as the default), and let each adapter declare what it needs.

NarrationFit planningAssemblyDoctor

Code: narration stage · Addis adapter · doctor

Medium

Partial runs check stages they won't run

What happens

plan --until brief failed because the music provider was misconfigured, even though music wasn't part of the run. The planner checks every stage before looking at the requested range.

The fix

Only resolve providers for the stages being run, and use that resolved plan during execution.

BriefMusicRunnerProvider registry

Code: plan and provider resolution

Medium

Style text leaks into unrelated shots

What happens

The bible's style description goes into every storyboard and keyframe prompt. When it mentioned brewing, unrelated keyframes gained inset brewing images. A plain full-frame style description cleared them.

The fix

Keep only the look (lighting, lens, treatment) in the bible, describe each action in its own shot, and review stills before animating.

Part 3

Under the hood: what a run actually does

Six things happen every time you type vidpipe run. Open the details for the function names.

  1. It reads your project and makes a plan

    The project folder is loaded, a tool is picked for each stage, and it checks each tool can do what the stage needs.

    Details

    cli.main() parses the command. Project loads the YAML and roots all paths. pipeline.plan() builds adapters from the registry and checks capabilities. plan --json adds a time and cost estimate.

  2. It runs the stages one by one

    Each stage reads the previous stage's files and writes its own. Where you've asked for approval, it pauses.

    Details

    pipeline.run() creates a stage context. Stages read typed models from build/ and register work through StageContext.produce(). The manifest tracks stage status, and approvals are tied to hashes of the approved outputs.

  3. It skips anything already made

    Before generating, it checks whether the same inputs already produced an output. A redo of one shot only changes that shot.

    Details

    The store fingerprints upstream files and values, provider identity and options, parameters and seed. It records file hashes, wall time, GPU time and retries. Redo bumps a shot's seed counter, so only that keyframe and its clips change.

  4. It fits the voice to the picture

    Using the real narration lengths, it splits lines at natural pauses and decides each shot's speed or whether it needs an extra clip.

    Details

    Shared visuals can serve both languages with per-language timings. A continuation clip starts from the final frame FFmpeg extracts from the previous clip.

  5. It sends media jobs to ComfyUI

    Image, video and music jobs are ComfyUI graphs. Vidpipe fills in the prompt, seed and images, waits for the result and retries if needed.

    Details

    A YAML mapping names each graph's inputs, outputs, capabilities and retry settings. The job runner polls ComfyUI, collects outputs, records attempts, and can step down once after running out of GPU memory.

  6. It assembles one video per language

    FFmpeg joins the shots, lowers the music under the voice and adds subtitles.

    Details

    The stage builds an AssemblyJob from the fit plan and media indexes. FFmpeg trims, retimes and joins shots, ducks the score and renders subtitles, with SRT sidecars next to each MP4.

Who Vidpipe talks to

Eight connections cross the boundary of Vidpipe. They're grouped by who is on the other side.

You

How you drive Vidpipe and what you get back.

Command line

Does
run, plan, doctor, redo shot, approve
How
Project path and flags in; reports on stdout, errors on stderr, status as the exit code. plan --json gives structured output.

cli.py

Project folder

In
Markdown brief, YAML config and bible, optional reference images.
Out
Working files in build/; one MP4 and SRT per language in out/.

project.py · models.py

Online AI services

Writing and speaking happen through services on the internet.

Gemini CLI, Claude Code, Codex CLI

Does
Script, storyboard, translation and its back-check.
How
Runs the signed-in CLI in an empty temp folder, sends the prompt on stdin, reads JSON or text back (Codex can also use a scratch file), then validates it against the stage's schema.

cli_text.py · translate.py

Microsoft Edge TTS

Does
English and Amharic narration by default.
How
The edge-tts library sends text, voice and prosody over the network; the MP3 is saved and measured locally.

edge.py

Addis Voices 2

Does
Amharic narration in this checkout; English still goes to Edge.
How
HTTPS JSON to POST /api/v1/voice/generations with the ADDIS_API_KEY header and a stable request ID per clip. The MP3 comes from a signed URL, fetched without the key.

addis.py

Local engines on this machine

Pictures, motion, music and the final cut are made locally.

ComfyUI

Does
FLUX.2 stills, Wan moving shots, ACE-Step music.
How
HTTP: images to /upload/image, graphs to /prompt, polling /history/{id} and /queue, files from /view. Can cancel and free memory; the doctor reads its node and model lists.

comfy/client.py · workflow format

FFmpeg and ffprobe

Does
Final assembly, last-frame extraction, checking clip lengths.
How
Local programs found through VIDPIPE_FFMPEG_DIR or PATH, given file paths and filter arguments; ffprobe returns media details as data.

assembly.py · comfy_i2v.py

Does
Call plan(), run(), redo(), approve() directly, or add new providers.

Plugins register through the vidpipe.providers entry-point group and exchange typed requests, results and capabilities. The song contract exists but only has a fake adapter so far.

Part 6

What to do next

  1. Protect the outputs. Verify file hashes on reuse and allow only one writer per project.
  2. Scope partial runs. Only check the stages a run will actually touch.
  3. Make narration per-language. Pick a voice provider for each language.
  4. Keep reviewing stills before motion. It's the cheapest point to catch a bad shot.

Evidence comes from temporary test projects and a rerun of the realistic demo. The audit changed no pipeline code.
